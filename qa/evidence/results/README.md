# results · 证据结果存放约定

文件名必须能一眼看出**用哪套布局跑的**，避免"非契约实现的结果"被当成验收证据：

| 文件名 | 含义 | 是否算验收 |
|---|---|---|
| `YYYY-MM-DD-evidence2-contract-v1.md` | 用默认契约布局（`CRYPTO-PACK` `YSPK/1.0`）跑的结果 | ✅ 算 |
| `YYYY-MM-DD-evidence2-<impl>-v1-noncontract.md` | 用旧/其它布局跑的结果，例如 `rune-v1-noncontract` | ❌ 只作记录与对照 |
| `YYYY-MM-DD-evidence1-*.md` | 证据一（服务端无明文/无文件名/无日志泄露） | 视参数是否齐备 |

规矩：

1. **同一份结论只放一个文件**，不覆盖历史：重跑就加新文件，旧的保留。
2. 非契约布局的结果，文件头必须写清"不作验收"以及"为什么"。
3. 结果文件里**不放密钥、不放明文**：只写错误名、字节数、偏移、路径（路径里不含
   用户内容），命中上下文最多左右各 8 字节的 hex。
4. 每份结果都要带**可复跑命令**与对象版本（分支 + commit）。
