## 三、`8f4f24c`（此前验过，结论复述）

内核 `c1b87d0a…`（**第一个把内核真正提交进 git 的 head**）、老库升级 10/10、向量套件全过；
偏差：错误名 **`REVOKED`**、迁移集仍含 `0004_drop_token_epoch.sql`、只换 secret 走 `INVALID`（旧语义）、

## 四、建议

**两个都不用；用 `06c9f56`（`5a42bb43…`）。**

理由按权重：

1. **只有 `06c9f56` 删掉了 `0004_drop_token_epoch.sql`**——`8f4f24c`/`4514848` 每次迁移都会先删列/删状态表再补回，
   已升的 `kid` 会丢；这是 P0 级回退，没修。
2. **只有 `06c9f56` 的名字是 `STALE`**（`REVOKED` 计数 0）；两个候选都是 `REVOKED`（各 7 处），与终值不符。
3. **只有 `06c9f56` 恢复路径不 500**（含 `uploader_ip IS NULL` 的 P0 修复）：`08d40e7→…` 升级 10/10 +
   `d655e16（真删列）→06c9f56` 恢复 12/12，旧凭据仍 401 `STALE`。
4. 内核入库这条三者都满足（`c1b87d0a…` 都被跟踪），但 `8f4f24c` 是"第一个入库"的历史节点，不是最优版本。

若一定要在两个候选里二选一（不推荐）：选 **`4514848`**——它与 `8f4f24c` 的三处关键缺陷相同，
但提交更新、迁移测试更全（`TestMigrateUpgradeFromOldSchema`）；**两者都必须接受**"删列迁移 + 名字不符 + 恢复 500"。

## 五、两个候选的已知偏差清单

**`8f4f24c`（`2c4e8c69…18ead`）**
1. 迁移集含 `0004_drop_token_epoch.sql` → 每次迁移删列/删状态表（P0 回退未修）；
2. 错误名 `AUTH_TOKEN_REVOKED`（7 处），与终值 `STALE` 不符；
3. 只换 secret → `AUTH_TOKEN_INVALID`（旧语义；终值是"不吊销"）；
4. 跑过 drop 的库恢复会 **500 INTERNAL**（缺 `uploader_ip NULL` 修复）；
5. 无 `0005_restore`，历史库无法自动恢复。

**`4514848`（`bcabb205…414804`）**
1. 同上第 1 条（`0004_drop` 仍在）；
2. 同上第 2 条（`REVOKED` 7 处、`STALE` 0 处）；
3. 同上第 3 条（secret → `INVALID`）；
4. 同上第 4 条（恢复 500，实测 11/12）；
5. 同上第 5 条（无 `0005_restore`）。
