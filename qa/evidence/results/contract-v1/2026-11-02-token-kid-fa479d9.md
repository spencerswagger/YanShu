## 1. 四步结果（每步只改一个变量，均需重启）

| 步 | 变量 | 旧 token 状态 | 错误名 | 补充 |
|---|---|---|---|---|
| ① 基线 | secret-A、kid=k1 | **201** | — | 上传 prelude 成功 |
| ② **只换 secret** | secret-A→B，kid 仍 k1 | **401** | **`AUTH_SIGNATURE_INVALID`** | 同时段新签发 → **201** |
| ③ **只换 kid** | kid k1→k2，secret 仍 B | **401** | **`AUTH_TOKEN_STALE`** | 上一轮新签发的 token 也 → 401 STALE |
| ④ 换 kid 后新签发 | kid=k2 | 新 token **201** | — | **最初 token 仍 401 STALE（不复活）** |

## 2. 部署项：不设 `YANSHU_TOKEN_KID` 会拒绝启动

```
$ YANSHU_TOKEN_SECRET=… yanshu-server          # 不设 KID
level=ERROR msg=fatal err="config: YANSHU_TOKEN_KID is required when serving
  (1..32 printable chars); rotate it together with YANSHU_TOKEN_SECRET to revoke all upload tokens"
exit=1
```

**fail closed 成立**：退出码 **1**，报错点名变量，并提示与 secret 一起轮换。

## 3. 结论与待跟进

- **状态：已验证（kid 机制，`fa479d9`）**。四步里"只换 kid → `AUTH_TOKEN_STALE`、新签发 201、
  旧 token 不复活"全部成立；"只换 secret"同样吊销，但错误名是 `AUTH_SIGNATURE_INVALID`。
- **待跟进一处（错误名归一）**：只换 secret 应报凭据类。Core 已在后续提交把
  `AUTH_SIGNATURE_INVALID` 改为 `AUTH_TOKEN_INVALID`（`97d156c` 线），届时用同一脚本复测即可。
- `AUTH_TOKEN_STALE` 已作为 **kid 轮换场景**的错误名记录（契约方补 §10.1）。
- 另注：`fa479d9` 的迁移**只有 `0001_init.sql`**（无 ALTER），本实验用的 schema 是从零建的；
  **老库升级仍缺列**，这条与二进制版本无关，仍未解决。
