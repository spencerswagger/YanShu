## 3. token 生命周期实测（最小实验）

**问题**：轮换 `YANSHU_TOKEN_SECRET` 后，已签发的 `upload_token` 会不会失效？

**做法**：同一 schema 上起两次实例（同一端口由脚本各取空闲端口），
第一次 `TOKEN_SECRET=a…` 建传输拿到 `upload_token`，第二次换 `TOKEN_SECRET=b…` 重启，
用**旧 token** 打受保护端点 `PUT /v1/transfers/{id}/prelude`。

**结果**：`HTTP 201` —— **旧 token 仍然可用**。

**结论**：轮换 `TOKEN_SECRET` **不会**吊销已签发 token；token 的校验依据是库里的 SM3 记录，
与 secret 无关。因此**"secret 泄露 → 一键吊销"目前做不到**，只能靠库层删除/过期。
这与我们此前"重启即失效"的假设不符，属**真实缺口**（Core 已在加 `kid`/epoch）。
复跑（已脚本化）：

```sh
python3 qa/evidence/check_token_lifecycle.py \
  --binary <yanshu-server> --dsn "<DSN>&search_path=gate_ev1" --ys-tool <ys-tool>
# 输出末行即结论：旧 token 仍可用 / 已失效
```

`kid`/epoch 落地后应改成「轮换 → 旧 token 立刻 401、新 token 200」，并在 `results/` 留一份新结果。
