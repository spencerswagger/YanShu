# ADR-0005：终结态判定与 ack 幂等重放的优先级

| 项 | 值 |
|---|---|
| 状态 | **已采纳**（2026-11-10） |
| 日期 | 2026-11-10 |
| 适用版本 | 服务端 v0.2.3 起（`POST /v1/transfers/{id}/ack`） |
| 关联文档 | `docs/API.md` §1.7.4（判定顺序）、§5.2（TTL 即时判定）、§7.5（ack） |
| 影响面 | 只澄清**既有条款之间的优先级**；不新增错误码、不改字段、不改包字节、不改状态机 |

---

## 1. 问题：三处条款在 `POST /ack` 上互相重叠

同一个请求（`POST /v1/transfers/{id}/ack`，传输已终态）同时被三条条款覆盖：

| 条款 | 说什么 |
|---|---|
| §1.7.4 判定顺序 | 终结态 → `410` **一律**，先于凭据（`401`）与 `409`；当事人判定（`403`）未提 |
| §5.2 TTL 即时判定 | 「到期后的 `POST /ack` → `410 TRANSFER_EXPIRED` 且**不计数**」（逐字） |
| §7.5 幂等 | 「同一 `download_id` 的重复 `ack` 只计一次**并返回 200**」 |

三条在「已 `CONSUMED` + 用同一租约重放」这一点上会撞：按 §1.7.4 该 `410`，按 §7.5 该 `200`。
实现必须有唯一解，而契约没写这个优先级——于是 #56 修四条上传路径时，`ack` 留成了「先判租约、回 `409`」，
两边都不满足。

## 2. 决定

### 2.1 默认：终结态 `410` 优先，且排在 `403` 之前

- 终结态（`REVOKED` / `EXPIRED` / `CONSUMED`）一律 `410` + 实际终态码；
- **当事人判定（`403 NOT_TRANSFER_PARTY`）排在 `410` 之后**：终结态下不因为「你不是当事人」改回 `403`。
- 依据不是"少暴露信息"（`GET /v1/transfers/{id}` 本来就无鉴权返回 tombstone 与 `terminal_reason`，终态本身不是秘密），
  而是 §1.7.4 的「**一律** 410」与 §1.7.4 开头「凭据类与**签名类**严格分开」——`403` 既不是凭据类也不是签名类，
  把它排在 `410` 之前会让"终结不可恢复"这条主规则出现例外。

### 2.2 唯一例外：`CONSUMED` 上的同租约重放 → `200`

- 传输已 `CONSUMED`，且请求带的 `download_id` **就是该传输已 ack 过的那个** → `200`，**不计数**（§7.5 幂等）；
- 换成别的 `download_id`（哪怕格式合法但不属于该传输 / 未 ack 过）→ `410 TRANSFER_CONSUMED`；
- `REVOKED` / `EXPIRED` 上即使该租约曾 ack 过，也一律 `410` —— 这两条由 §5.2 逐字要求，不能被幂等条款覆盖。

**为什么例外只给 `CONSUMED`**：`CONSUMED` 是 `ack` 自己造出来的终态，重放同一个租约是"同一次操作的重试"；
`REVOKED` / `EXPIRED` 是**别人/时间**造成的终结，与这次 ack 无关，按 §1.7.4「终结不可恢复」处理。

## 3. 落地与门禁

- 实现：`server/internal/httpapi/handlers_transfers.go` 的 `handleAck`（终态分支里只放行 `CONSUMED` + 本传输租约的幂等重放）；
- 契约：`docs/API.md` §1.7.4 顺序句、§7.5 新增一条 bullet（本 ADR 同 PR 落）；
- 门禁：`server/internal/httpapi/ack_terminal_precedence_test.go`
  - `TestAckTerminalStatePrecedesLease`：3 终态 × 无/伪租约 = 6 例，断言 `410` + 终态码 + 不计数；
  - `TestAckTerminalBeatsPartyCheck`：非当事人持**本传输有效租约**在终态上 ack → `410`（不是 `403`）；
  - `TestAckConsumedReplayStaysIdempotent`：同租约重放 `200` 且不计数、换租约 `410` 且不计数；
  - `TestAckNonTerminalStillChecksLease`（阴性对照）：未终结缺租约仍 `409`、有效租约仍 `200` 且 `+1`。

## 4. 不做的选项

| 选项 | 为什么不选 |
|---|---|
| 让 §7.5 幂等覆盖所有终态（`REVOKED`/`EXPIRED` 重放也 `200`） | 与 §5.2「到期后 ack → `410` 且不计数」逐字冲突；且会让"已撤回的包"在客户端看起来仍可取件 |
| 让 §1.7.4 覆盖所有情况（`CONSUMED` 重放也 `410`） | 与 §7.5 逐字冲突，且会把"网络重试"变成客户端可见的失败（真实场景：ack 成功但响应丢了） |
| 不写进契约，只靠实现约定 | 下一个人按 §10「非接收方调 ack → `403`」就会把顺序改回去，现有用例抓不到（这正是本 ADR 的由来） |
