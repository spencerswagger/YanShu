# ADR-0002 · 全平台统计的计数口径、对账与审计保留

| 项 | 值 |
|---|---|
| 状态 | **已采纳**（v5 口径，2026-11-10 夜班补） |
| 日期 | 2026-11-10 |
| 适用版本 | 服务端 v0.2.x 起（`GET /v1/stats`）、迁移 `0007` |
| 关联文档 | `docs/API.md` §0.4（客户端时间基准）、§4.6（`/v1/stats`）、§5.2（保留与脱敏）、§12 |
| 影响面 | 只补契约与决策记录；不改任何既有字段、不改包格式、不改文案 |

---

## 1. 背景

v5 加了两个长期行为：**终结元数据永久保留（+30 天脱敏）** 与 **全站聚合统计 `/v1/stats`**。这两件事都会让"服务端存了什么、存多久"发生变化，而原契约只写了 7 天墓碑清理。本 ADR 把三件容易在实现里走偏的事定死：

1. 统计数字**怎么算**（口径）、**能不能信**（漂移）；
2. 计数器是**派生数据**，与真实行的关系；
3. 匿名只读端点**要不要写审计**，审计本身**留多久**。

---

## 2. 决策

### 2.1 统计口径：只计 `CONSUMED`，`created` 单列

| 字段 | 口径 | 为什么不合并 |
|---|---|---|
| `consumed` | `state = CONSUMED` 的行数（接收方 `ack` 达上限，即真的送达） | — |
| `consumed_bytes` | 这些行的 `plaintext_size` 之和（**明文**口径） | 密文口径含 tag 与 padding，与用户理解的"文件多大"不一致 |
| `created` | `POST /transfers` 成功次数 | 与 `consumed` 是**两种事实**：发起了 ≠ 送达了。合成一个数会让"传了多少文件"虚高（过期/撤回也算进去） |

**明确排除**：`EXPIRED`、`REVOKED` 不计入 `consumed`。它们已经终结但没有送达，计入即失真。

`today` 的日界是 **UTC 00:00:00Z**，`total` 是全历史；两者同一口径。

### 2.2 日界必须显式 UTC，不能吃数据库会话时区

`::date` 强转会按会话 `TimeZone` 截断。回填用 `terminal_at::date`、运行时用进程 UTC 时间——若数据库会话不是 UTC，**同一个"今天"会被分到两个桶**，且回填与运行时各错各的。

**决策**：日界计算 MUST 显式 UTC 化（`(ts AT TIME ZONE 'UTC')::date` 或连接级固定 `TimeZone=UTC`），**MUST NOT** 依赖部署环境的默认时区。这一条写进 `API.md` §4.6，属可测项（构造非 UTC 会话跑一次对账即可暴露）。

### 2.3 计数器是派生数据：必须对账

计数器（`stats_counters`，一天一行）与 `transfers` 真实行是**主从关系**：计数器是缓存出来的派生值，`transfers` 是事实。

- 写入与业务同事务（建包 `+created`，`ack` 达上限 `+consumed/+bytes`），因此正常路径不会漂移；
- 但**漏加/重放/手工改库/迁移回填口径变化**都会让两者分叉，且不会自己报错；
- 因此 MUST 有**每日对账**：`count(*)`/`sum(plaintext_size)` 与计数器比对，偏差 > **0.1%** 报警。

**为什么不直接查 `transfers`**：10 万/日 → 一年 3650 万终态行，`count(*) + sum()` 即使走索引也要扫全量，单次数百 ms 且随年限线性变差；首页按 10 QPS 就是每秒 10 次大范围扫描。计数器把读降到 O(1)（一年 365 行）。

### 2.4 匿名只读端点不写审计

`audit_events` 目前**没有保留期**（sweeper 不清理），每请求一行、永久增长。`/v1/stats` 是**匿名 + 首页轮询**的端点，若沿用"每请求审计"的全局中间件：

- 实测（本机，`yanshu_test`）：20 次匿名 `GET /v1/stats` → `audit_events` **+20 行**；
- 换算到 10 QPS 的首页流量 ≈ **86 万行/天**，与业务量无关，纯粹是读流量；
- 该表还带 `ip` 列，等于把匿名访客的 IP 长期留档。

**决策**：

1. `/v1/stats`（以及同类**匿名只读、无个例信息**的端点，如 `/v1/config`）**MUST NOT** 每请求写审计行；只保留访问日志（进程日志，按 `YANSHU_LOG_RETENTION_DAYS` 滚动）。
2. `audit_events` **必须有保留期**（建议 90 天，随 sweeper 清理）；没有保留期的审计表迟早变成第二张大表，且带 IP。
3. 审计仍然覆盖**有身份、有副作用**的请求（注册、建包、上传、下载、ack、revoke、举报、改昵称）——这些是安全事件来源，不能省。

### 2.5 永久保留的边界（重申，不新增）

- 永久保留的是**元数据**：时间、大小、块数、状态、码、计数。表里从来没有文件名/MIME/明文/密钥/密文，所以"永久"不涉及内容留存。
- 30 天脱敏的三列（`uploader_ip`、`prelude_sm3`、`upload_token_sm3`）对客户端**不可观测**：tombstone 响应字段集本来就不含它们（§7.2）。
- **残余风险（已知、接受）**：脱敏后 `sender_code`/`recipient_code` 仍在，长期可查"某码给某码发过多少次"。缓解是码可轮换（换密钥对即换码），历史码不指向具体人。若后续要求更严，再加"列表只展示 90 天、统计永久"，属产品决策，不在本 ADR 内。

---

## 3. 后果

| 项 | 后果 |
|---|---|
| 实现侧待办 | `/v1/stats` 失败码用 `503 SERVICE_UNAVAILABLE`（不是 500 `INTERNAL`）；日界显式 UTC 化；审计中间件按路由白名单跳过匿名只读端点；`audit_events` 加保留期清理；每日对账任务 |
| 测试侧待办 | 非 UTC 会话下的日界用例；对账偏差用例；匿名请求不产生审计行的断言 |
| 客户端影响 | 无。数值只做量级化展示，失败静默降级（整块隐藏） |
| 迁移影响 | `0007` 只 `DROP NOT NULL` 两列 + 建计数器表 + 一次性回填；可重复执行（`ON CONFLICT DO UPDATE`） |

---

## 4. 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 直接 `SELECT count(*), sum(...) FROM transfers` 实时算 | 随年限线性变差，首页 QPS 下不可接受（§2.3） |
| 把 `created` 与 `consumed` 合成一个"传输数" | 口径不同，合并即失真（§2.1） |
| 统计端点沿用全局每请求审计 | 读流量写满审计表 + 匿名 IP 长期留档（§2.4） |
| 终结行继续 7 天物理删除 | 与"历史记录/永久统计"需求冲突；且删行会让聚合结果随时间变小 |
| 永久保留但**不**脱敏 | `uploader_ip` 可还原"某 IP 何时给谁发过"，`prelude_sm3` 是内容指纹，长期留存无正当性 |
