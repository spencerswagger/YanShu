# 界面文案（唯一权威）

本文件是界面文案的**唯一权威**：代码里出现的这些位置必须与下表逐字一致。改文案先改这里，再改代码，不一致视为缺陷。

基调：中性、专业、准确。禁止口语化/卖萌（“我要发”“点我”），禁止堆古风辞藻（不把“发送”写成“传书”）。按钮用动宾短语，状态用陈述句。

## 主流程（11 处，v1 定稿）

| # | 位置 | 文案（逐字） | 说明 |
|---|---|---|---|
| 1 | 主按钮（首屏操作区） | `发送文件` | 动宾短语，不预设发送结果 |
| 2 | 次要按钮（首屏操作区） | `接收文件` | 与主按钮同词性，语义对称 |
| 3 | 卡片标题 · 操作区 | `选择操作` | 中性，不替用户判断意图 |
| 4 | 卡片标题 · 我的码 | `你的接收码` | 名词短语即结论，说明这串数字的用途 |
| 5 | 卡片标题 · 统计 | `今日已完成 2 次` | 陈述句带数字；数字由真实计数替换 |
| 6 | 卡片标题 · 发送中 | `加密并上传中` | 准确描述当前阶段，不说“已发送” |
| 7 | 卡片标题 · 接收 | `1 个文件待接收` | 数字前置；数量由真实待收数替换 |
| 8 | 空态（接收列表为空） | `暂无待接收文件` | 陈述现状，不推销下一步 |
| 9 | 失败态（昵称保存 · 挑战过期） | `签名挑战已过期，已重新获取，请重试` | 原因 + 已做的补救 + 下一步 |
| 10 | 成功态（昵称保存） | `昵称已更新` | 陈述结果，不加语气词 |
| 11 | 安全小字（全站唯一一处） | `端到端加密，私钥仅存于本机浏览器` | 一句话含“加密范围 + 私钥位置” |

配套（非 ★ 表项，但同样定稿）：昵称输入超限提示 `昵称过长` + `上限 16 字符，当前 N，请删减后保存。`；
发送完成态 `已发送，等待对方接收`；接收完成 `已保存至本机`。

## 举报入口（契约 §11.5）

| # | 位置 | 文案（逐字） | 说明 |
|---|---|---|---|
| R1 | 待收项里的入口 | `举报` | 文字按钮，收在卡片次要位置，不上首屏 |
| R2 | 弹层标题 | `举报此文件` | 说明作用对象 |
| R3 | 原因选项 | `骚扰或辱骂` | `reason=ABUSE` |
| R4 | 原因选项 | `涉及未成年人` | `reason=CSAM` |
| R5 | 原因选项 | `疑似恶意软件` | `reason=MALWARE` |
| R6 | 原因选项 | `其他原因` | `reason=OTHER` |
| R7 | 备注输入提示 | `补充说明，可留空` | 可选字段，限长 200 |
| R8 | 提交按钮 | `提交举报` | 动宾短语 |
| R9 | 成功提示 | `已记录，我们会处理` | 后面会附编号，如「已记录，我们会处理（编号 r_1a2b3c4d）」 |
| R10 | 弹层底部说明 | `举报只做记录，不会删除对方文件，也不会改变传输状态。` | 明确举报不具删除效力 |
| R11 | 失败态 · 码不一致 | `签名里的码与请求不一致，请刷新页面后重试` | `AUTH_CODE_MISMATCH` |
| R12 | 失败态 · 签名无效 | `签名校验未通过，请刷新页面后重试` | `AUTH_SIGNATURE_INVALID` |
| R13 | 失败态 · 限速 | `请求过于频繁，请 N 秒后再试` | 429 且带 `Retry-After`；无该头时用 `请求过于频繁，请稍后再试` |
| R14 | 失败态 · 网络/其他 | 复用 `describeError()` 的标题与提示 | 不吞错、不只 console |
