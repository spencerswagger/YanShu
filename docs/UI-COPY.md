# 界面文案（唯一权威）

代码里出现的这些位置必须与下表**逐字一致**；改文案先改这里，再改代码，不一致视为缺陷。

> 说明：本文件当前只含**举报入口**这一批（`feat/abuse-report-ui`）。主流程的 11 处文案在
> `feat/ui-redesign`（PR #26）的同名文件里，两者合入时按位置合并即可（本文件表格结构相同）。

基调：中性、专业、准确。禁止口语化/卖萌，禁止堆古风辞藻。按钮用动宾短语，状态用陈述句。

## 举报入口（契约 §11.5）

| # | 位置 | 文案（逐字） | 说明 |
|---|---|---|---|
| R1 | 待收项里的入口 | `举报` | 文字按钮，收在卡片次要位置，不上首屏 |
| R2 | 弹层标题 | `举报此文件` | 说明作用对象 |
| R3 | 原因选项 | `骚扰或辱骂` | `reason=ABUSE` |
| R4 | 原因选项 | `涉及未成年人` | `reason=CSAM` |
| R5 | 原因选项 | `疑似恶意软件` | `reason=MALWARE` |
| R6 | 原因选项 | `其他原因` | `reason=OTHER` |
| R7 | 备注输入提示 | `补充说明，可留空` | 可选字段，限长 200 |
| R8 | 提交按钮 | `提交举报` | 动宾短语 |
| R9 | 成功提示 | `已记录，我们会处理` | 后面会附编号，如「已记录，我们会处理（编号 r_1a2b3c4d）」 |
| R10 | 弹层底部说明 | `举报只做记录，不会删除对方文件，也不会改变传输状态。` | 明确举报不具删除效力 |
| R11 | 失败态 · 码不一致 | `签名里的码与请求不一致，请刷新页面后重试` | `AUTH_CODE_MISMATCH` |
| R12 | 失败态 · 签名无效 | `签名校验未通过，请刷新页面后重试` | `AUTH_SIGNATURE_INVALID` |
| R13 | 失败态 · 限速 | `请求过于频繁，请 N 秒后再试` | 429 且带 `Retry-After`；无该头时用 `请求过于频繁，请稍后再试` |
| R14 | 失败态 · 网络/其他 | 复用 `describeError()` 的标题与提示 | 不吞错、不只 console |
